# Кондуит

Внутренняя версия кондуита математического кружка 11 класса, 2026/27.
Учёт плюсов на занятиях: кондуит по сериям, общий рейтинг и пересчёт рейтинга
по любому подмножеству серий и тем.

Сервера и базы данных нет. GitHub Pages раздаёт репозиторий как есть, страница
читает файлы из `data/` и считает всё в браузере читателя. Читать может кто
угодно по ссылке, писать — только владелец репозитория.

## Счёт

Вес задачи = **max(n − число решивших, 1)**, где n — сколько человек занималось
по этой серии, то есть длина её списка. Задачу, которую сдали трое из двадцати,
она оценит в 17; задачу, которую сдали все, — в 1: решена же.

Список свой у каждой серии, поэтому и n у них разное: задача, которую давали
десятерым, и задача на весь кружок стоят по-разному. Гробы к занятию не
привязаны и считаются от всего списка группы.

У задачи бывает **своя цена** — тогда формула к ней не применяется. Формула
знает одно: сколько человек сдали. А задача бывает дорога и не поэтому. Своя
цена ставится у каждой задачи отдельно, и её всегда можно вернуть к формуле.
Ноль руками поставить можно: это не то же самое, что «нет своей цены».

У гроборешения бывает **надбавка** — сколько добавить за конкретное «кто взял
этот гроб». Она прибавляется к цене гроба и достаётся только тому, кому
поставлена.

В рейтинге сначала очки, при равенстве — по алфавиту; одинаковых мест не
бывает. В кондуите ученики стоят по алфавиту: там ищут человека, а не место.

## Что где лежит

```
index.html          сайт: рейтинг, кондуит по сериям, гробарий, зачёт, карточка
edit.html           редактор: ввод с телефона
open.html           ссылка для рассылки: уводит из встроенного браузера в Chrome
manifest.webmanifest  установка на домашний экран
assets/             стили и скрипты
  icons.js          значки тем: спрайт и выбор
  fonts/            Golos Text, два файла по диапазонам
data/
  config.json       название, репозиторий, отметка сборки
  students.json     ученики
  types.json        темы: разделы и подразделы, у каждого цвет и значок
  graves.json       гробарий: задачи вне серий и кто их взял
  series/NN.json    одна серия
  series/manifest.json  список файлов серий
  pdf/*.pdf         листки серий и гробария
  zachet.json       список файлов зачёта
  zachet/*.pdf      файлы зачёта
tools/build.py      версия статики (после правки стилей и скриптов)
```

Формат серии:

```json
{
  "n": 7,
  "series": 5,
  "given": "2026-09-12",
  "date": "2026-09-15",
  "held": true,
  "roster": ["ivanov-artem"],
  "present": ["ivanov-artem"],
  "problems": [
    { "id": "0", "type": "algebra", "sub": "inequalities", "exercise": true },
    { "id": "2а", "type": "comb", "sub": "graphs", "exercise": false, "weight": 12 }
  ],
  "pdf": { "file": "seriya-07.pdf", "size": 124035, "at": "2026-09-12" },
  "solved": { "ivanov-artem": ["2а"] }
}
```

`series` — номер серии, он и виден на сайте. `n` — служебный слот: он же имя
файла и ключ внутри редактора; менять его нельзя, иначе перенумерованная серия
потеряет свой файл. `given` — когда серию выдали, `date` — когда было занятие.
`weight` есть только у задач со своей ценой.

**Список серии** (`roster`) — кто по ней занимался. Заводится он с общего списка
на тот день, когда серию завели, и дальше за ним не следует: уехавшие на сборы,
финал или турнир занятие не пропустили — его у них просто не было. Из этого
списка считается n, по нему же построен кондуит. Общий список задаёт имена:
переименование ученика видно сразу всюду, а состав прошлых серий не трогает.

**Посещаемость** (`present`) — последний столбец кондуита, рядом с плюсами. По
умолчанию отмечены все: снимать проще тех, кого не было. В карточке ученика
видно «Занятия n / m», пропущенная серия помечена «не был», а в рейтинге есть
отбор «где все были» — по сериям, на которых был весь их список.

**Занятие ещё не прошло** (`held: false`) — серию выдали, темы расставлены,
листок приложен, а кондуит по ней на сайте не показывается и нигде не считается.
Вкладка «Сохранение» напомнит, если в такой серии уже стоят плюсы.

Выбывший ученик помечается в `students.json` полем `out`, а не стирается: его
имя стоит в кондуитах тех занятий, где он был. В общем списке и в рейтинге его
больше нет; вернуть — завести с тем же именем.

Упражнение узнаётся по номеру: числовая часть равна нулю (`0`, `0а`) — значит
упражнение. Поле `exercise` лишь повторяет это в файле.

Задача, чей подраздел удалили из тем, остаётся **без темы**: в рейтинг она не
идёт, пока ей не выберут тему заново, но в кондуите видна — с серым пустым
квадратом вместо значка. Вкладка «Сохранение» показывает такие задачи списком.

## Редактор

`edit.html` открывается в браузере телефона. Один раз нужно вставить
fine-grained токен GitHub с доступом только к этому репозиторию и правом
**Contents: Read and write** — вкладка «Сохранение». Токен лежит в localStorage
телефона и уходит только на `api.github.com`; если телефон потерялся, токен
отзывается в настройках GitHub.

Правки живут в памяти страницы и уезжают **только по кнопке «Сохранить»** во
вкладке «Сохранение»: она одна отправляет всё накопленное — учеников, темы,
серии, гробарий, зачёт. Уход со страницы теряет несохранённое, ничего
не переспрашивая; переключение между вкладками и сериями — нет. Рядом кнопка
отката. Между сохранениями две минуты перерыва.

- **Серии** — лента по номерам. «+ серия» заводит новую сразу в ленте, в
  репозиторий она уедет по кнопке сохранения. Первое «+ задача» даёт упражнение
  (номер 0), дальше номера идут подряд. «+ пункт» превращает задачу `5` в `5а` и
  добавляет `5б`; пунктов не больше шести. Касание клетки ставит и снимает плюс,
  последний столбец — посещаемость. Внизу экрана листок серии и её список: их
  правят редко, потому они и внизу.
- **Гробы** — задачи вне серий, копятся весь год. Там же листок гробария и
  список гроборешений: кто, какой гроб, какая надбавка.
- **Зачёт** — pdf, которые надо раздать.
- **Темы** — разделы и подразделы. У каждого свой значок: он выбирается кнопкой
  слева от названия, из общей россыпи. У нового раздела значок выбирается сразу,
  вместе с цветом; новый подраздел заводится пустым квадратом, и знак ему дают
  тут же, в строке. Удаление раздела освобождает его цвет; последний раздел
  удалить нельзя.
- **Ученики** — список группы. Имя правится прямо в строке: id при этом не
  меняется, поэтому плюсы не теряются. Плюсы удалённого остаются в файлах серий:
  считаться перестают, но вернутся, если завести человека снова.
- Любой pdf выбирается прямо с телефона, до 8 МБ, и уезжает той же кнопкой
  сохранения. Файлы уходят раньше записей, которые на них ссылаются.
- Приложенный листок везде так и называется — «Листок»: чей он, видно по месту.
  Осмысленное имя получает скачанный файл: «Серия 5.pdf», «Гробарий 1 сентября
  2026.pdf». Имя файла в репозитории закреплено за записью, поэтому новый листок
  просто ложится поверх старого.
- Удаление где угодно спрашивает дважды: крестик раздваивается на «удалить» и
  «передумал».

## Чтобы редактором нельзя было испортить сайт

- Список серий не считается по памяти страницы: при каждом сохранении он берётся
  из самой папки `data/series`, плюс записанное сейчас, минус удалённое. Любое
  расхождение уходит при ближайшем сохранении само. Пустой список не пишется.
- Файл, о котором редактор не знает, не переписывается: это всегда чужие данные.
- Непрочитанное не правится: если список серий, гробарий или зачёт не
  загрузились, вкладка показывает сообщение, а не пустой список.
- Настройки не пишутся памятью страницы: файл перечитывается перед записью, и
  меняется в нём одно поле — то, которое правили.
- Сайт переживает порчу данных: пропавший файл серии пропускается, пропавший
  список серий — тоже; страница откроется без серий, но откроется.

## Одно исключение из всех правил

Корона стоит у первого места — и у Аксёновой Елизаветы, всегда, независимо от
места. Внизу её карточки всегда стоит «Totus tuus». Оба заданы в коде
(`HONOURED` в `assets/app.js`), а не настройкой: настройка, у которой одно
верное значение и то навсегда, — не настройка, а лишний рычаг, который однажды
дёрнут по ошибке. Прежний переключатель в подвале редактора убран, и вместе с
ним — единственный путь, которым правка со старой страницы могла затереть
отметку сборки: она лежит в том же `config.json`, который тот переключатель и
писал. Редактор этот файл больше не трогает вовсе.

Ключ — id ученика, а не имя: переименование в редакторе id не меняет, поэтому и
корона с подписью его переживают. Если Елизавету обойдут, корон на странице
окажется две — одна за место, другая просто так.

## Оформление

Страница рассчитана на **Chrome** — и на телефоне, и на компьютере. Прежняя
осторожность с градиентами была нужна из-за Samsung Internet: тот в
принудительной тёмной теме гасил именно их. Это требование снято, и оформление
построено на прозрачности.

Подложка — тетрадная клетка и три пятна мягкого света, всё это неподвижно (как
именно — ниже, среди правил).

Панели — матовое стекло: полупрозрачная заливка, светлая грань поверху вместо
рамки и мягкая тень. Размытие того, что под панелью, осталось только у полосы
вкладок; всем прочим хватает прозрачности и грани. Задано оно одной переменной
`--pane-blur`: поставить в ней `none` — и стекло станет просто прозрачным,
ничего не разъедется.

Полоса вкладок — плавающая пилюля: она висит над содержимым, и под ней всё
проезжает. Выбранная вкладка помечена указателем, и указатель этот один на всю
полосу — он переезжает с вкладки на вкладку.

Переход браузера (View Transitions) здесь пробовался и убран совсем: он
подменяет снимками всё окно — из-за этого дёргалась шапка, замирал указатель и
путалась прокрутка при открытии ученика из середины списка. Любая смена экрана
теперь одна и та же: содержимое уходит за 90 мс и приходит новое, а шапка,
полоса вкладок и указатель всё это время остаются живыми элементами страницы.

Украшающего цвета нет вовсе — только свет. Пятна на подложке белые, панели
подсвечиваются белым, у каждой светлая грань сверху, тёмная снизу и косой блик
поверх.

**Цвет разрешён в шести местах, и список закрыт.** Он ведётся здесь нарочно:
первый раз подкраска расползлась по всем панелям и потребовала отдельной
уборки. Новое место для цвета появляется только вместо старого.

1. Значок темы и плашка раздела — восемь цветов разделов, **по три значения на
   каждый**: `--sN` — линия значка (на светлой теме тёмная, на тёмной светлая),
   `--fN` — заливка плашки, глубокая и плотная, `--gN` — свет в её углу, светлый
   тон той же семьи.

   Три, а не одно, потому что выводить заливку из цвета линии пробовали дважды
   и оба раза получалась не та глубина: то пыльно, то жидко. Плашки, с которых
   всё пошло, — «Место», «Самый ценный плюс», листок — собраны иначе: цвет задан
   прямо, а свет в углу другого, более светлого тона. Восемь разделов сделаны
   так же. Ярлык раздела — такая же плотная плашка, как «Место» в карточке
   ученика: цвет раздела, утемнённый до плотности, при которой белые буквы
   читаются, тот же косой блик и то же пятно в углу. Сам `--s`-цвет для заливки
   не годится — он средний по тону, подобран под тонкие значки и полоски, и
   белое на нём висит на грани. Плашек четыре из двадцати, между ними стоят
   неподкрашенные подразделы, поэтому ряд не рябит.
2. Золото первого места: номер и полоска в его строке.
3. Золото плитки «Процент», когда взята половина задач.
4. Красное удаление — плотная плашка (ниже).
5. Плитки «Место» и «Самый ценный плюс» — плотные плашки.
6. Ромб редактора в шапке: отличает его страницу от сайта одним взглядом.
7. Красная точка в знаке «МЦ :re» — она часть логотипа и потому живёт отдельно
   от всей палитры.
8. Сине-зелёная плашка строки с файлом — листка серии, гробария, файла зачёта.
   Тон уведён так, чтобы не совпасть ни с одним из восьми цветов разделов:
   листок разделом не является.

**Плотная плашка** — единственный вывернутый блок: белый текст на цвете там, где
всё остальное чернила по светлому. Приём вернулся из старого заголовка сезона
(`9a9fd6d`) и работает ровно пока таких блоков мало. Собрана она из того же, что
и панель, — заливка, косой блик, светлая грань поверху, — но заливка плотная,
0.82 против 0.6: сквозь неё клетка почти не видна, и плашка читается как
предмет, а не как окно. Отличает её от простой краски мягкое пятно второго цвета
в углу; резких краёв у него нет, поэтому оно читается светом, а не фигурой.

Цвет приходит двумя переменными (`--solid-bg`, `--solid-glow`), так что плашку
можно направить куда угодно, не трогая правило. Сейчас направлений три:
холодное индиго с голубым пятном у «Места», тёплая терракота с янтарным у
«Самого ценного плюса», багровое с тёплым у всех кнопок удаления. Температуры
не случайны: место — итог и сравнение с другими, лучший плюс — один свой вечер,
удаление должно выглядеть раскалённым.

В карточке ученика плашки стоят по краям ряда, а четыре подробности между ними
остаются стеклянными: ряд получает начало и конец вместо шести равных коробок.

Подложка нарочно не белая и с заметной клеткой: сквозь прозрачную панель должно
быть что-то видно, иначе стекло сливается с фоном и перестаёт быть стеклом.

Панель одна на всех, буквально до последнего значения: карточка, плитка,
таблица рейтинга, кондуит и любая панель редактора — это `rgba` одного и того
же цвета. Механика подкраски отсюда убрана совсем. Она была: пять слотов
оттенка, все белые, — но белый в них означал не «без цвета», а «на треть
светлее», и подкрашенные панели заметно выбивались из ряда, особенно на вкладке
серий. Редактор, где подкраски не было никогда, оттого и выглядел собраннее
основной страницы. Когда цвет понадобится, его добавят точечно и осознанно, а
не всем панелям заодно.

Цена оформления на телефоне держится в трёх правилах.

**Размытие подложки — только у полосы вкладок.** Под ней проезжает содержимое,
и там оно работает. У панелей его нет: под ними ровный свет и клетка, размывать
нечего, а платить пришлось бы на каждом кадре и заново при каждой вставке панели
в страницу. Прозрачность, грани и блик держат стекло и без размытия.

**Экран приходит и уходит целиком, одним слоем.** И уход, и приход — это одна
прозрачность и один сдвиг на всём `#main` сразу, а не движение у каждой панели
по отдельности. Поэлементного появления здесь нет нарочно: пока экран
проявлялся по частям, было видно, как страница складывается — особенно на
рейтинге, где строк три десятка. Собран он всегда до того, как начинает
проявляться.

**У каждой темы свой значок.** Раньше тему обозначал цветной кружок: он говорил
раздел, но молчал о подразделе, а в карточке ученика у подразделов не было и
кружка. Теперь на этом месте стоит знак — икс у алгебры, куб у стереометрии,
счётные палочки у подсчёта, — и он говорит и то, и другое. Цвет раздела при этом
никуда не делся: значок нарисован `currentColor` и красится обычным `color`.

Рисунки лежат в `assets/icons.js` по одному разу — в спрайте из `<symbol>`,
вставленном в страницу при первом обращении. Значок на экране это `<svg><use>`,
две строчки разметки: на рейтинге их разом бывает под сорок. Заливка и обводка
наследуются внутрь `<use>`, а селекторы — нет, поэтому у закрашенных фигур
`fill` задан атрибутом прямо в разметке символа.

Какой значок какой теме — записано в `data/types.json` полем `icon`, а не в
коде. Иначе новая тема, заведённая с телефона, оставалась бы без знака до
правки скриптов. Ключ значка говорит, что нарисовано (`cube`, `tally`, `graph`),
а не какая это тема: так он переживает переименование.

**Фон — закреплённая заливка самого `html`, а не слой поверх страницы.** Он
неподвижен: не прокручивается с содержимым и не смещается, когда на телефоне
появляется и исчезает адресная строка. Закреплённым слоем (`position: fixed`)
этого не добиться — такой слой браузер как раз и двигает вслед за окном. Рисунок
простой, две линии и три пятна, поэтому закреплённая заливка обходится дёшево.

**Стекло у кнопок одно на всех.** Ярлык отбора, «все» и «ни одной», «+ задача»,
«Выбрать pdf», квадратная кнопка, счётчик надбавки — всё это одна поверхность,
собранная из того же, что и панель: полупрозрачная заливка, косой блик, светлая
грань поверху вместо тени (`--glass`, `--glass-edge`, `--glass-top`,
`--glass-sheen`). Кнопки различаются размером и тем, чем показывают состояние, —
но не материалом.

До этого материала у них было три разных: у ярлыка отбора своя рамка, у «все»
рамки не было вовсе, а у кнопок редактора не было стилей вообще — «+ задача» и
«Выбрать pdf» рисовались системными серыми кнопками браузера, шрифтом Arial и
рамкой outset.

Состояние сказано плотностью: **включено — стекло, выключено — пустая рамка**,
ни блика, ни грани, заливки нет вовсе, надпись перечёркнута. Пунктирной рамки у
выключенного больше нет — другой тип штриха выбивался из общего вида. И
насыщенность шрифта в состоянии не участвует: от неё слово меняет ширину, и
соседние кнопки при каждом нажатии разъезжались.

**Кнопка лежит на панели, а не в одной плоскости с ней.** Раньше у неё была
только внутренняя грань поверху, и на стеклянной панели она читалась плоской —
отсюда и «блёкло и дёшево». Теперь под ней две тени: близкая держит край,
дальняя отрывает от панели. Выключённый ярлык теней не получает вовсе, и это
второй способ отличить его от включённого.

**Заливка кнопки полупрозрачна в обеих темах.** Сквозь неё должна быть видна
клетка, иначе это не стекло, а белая карточка (или, на тёмной теме, дыра в
панели): пробовали и почти непрозрачную белую, и тёмную лунку — обе читались
контрастно и мертво. Держат кнопку не заливкой, а ободом и тенью под ней.

Размеры: ярлык раздела 15,5-м и вторым набором, подраздела 13-м, кнопка
действия ростом 40 — вровень с полем ввода и главной кнопкой, рядом с которыми
она стоит в строке редактора. Ярлыки набраны средней насыщенностью с
отрицательным трекингом: на обычном начертании и 12–13 кегле они читались
системными виджетами, а их на экране два десятка — из них и складывалось первое
впечатление от страницы.

**«Все» и «ни одной» из кнопок стали строкой.** Шапка раздела читается одной
типографской строкой: название капителем вразрядку, действия тем же капителем
следом. Ни коробки, ни подчёркивания, ни линейки между ними — всё это пробовали
по очереди, и каждый раз добавленное спорило с соседним: коробка ставила
действие в один вес с ярлыками отбора, которым оно подчинено, подчёркивание
дублировало линейку, линейка перегораживала шапку. Осталась только разница
кегля и цвета. Поле под палец при этом во всю высоту строки, 30 пунктов.

**У кондуита нет заливки в шапке.** Непрозрачная осталась от времён, когда
столбец с номерами задач был липким и под него подъезжали строки. Липкость
убрали, заливка осталась — и на широком экране, где таблица уже панели,
обрывалась посреди стекла резкой вертикалью. Шапку отделяет черта снизу, и её
достаточно.

**Строка с файлом — плашка, а не строка списка.** На вкладке серии это
единственное, за чем туда заходят, и выглядеть оно должно как предмет, который
берут. Слово «скачать» заменено стрелкой: оно объясняло то, что и так очевидно —
строка одна, действие у неё одно. У добавляющих плюс вынесен из подписи в отдельный
знак, крупнее текста и тише по цвету: глаз ловит столбик плюсов, а «задача»
остаётся словом.

Цвет раздела живёт только в значке. Ни заливки ярлыка, ни подкрашенной рамки:
и то и другое пробовали, десяток подкрашенных плашек в ряд рябит и спорит с
самим кондуитом, где цвет что-то значит.

Единственная кнопка не из стекла — «Сохранить»: она залита чернилами целиком.
Это единственное действие, которое уводит правки в репозиторий, и путать его с
остальными нельзя.

Пилюли остались за полосой вкладок и мелкими действиями.

**Шапка — знак «МЦ :re».** «МЦ» набрано, «:re» нарисовано в svg: начертание в
знаке заданное, и подбирать под него гарнитуру, которая на чужом телефоне
окажется другой, бессмысленно. Тонкая линия одной толщины, торцы срезаны прямо,
верхняя точка двоеточия красная, нижняя — цвета текста, поэтому на тёмной теме
знак выворачивается сам. Названия сезона в шапке больше нет: оно осталось у
вкладки браузера, где и нужно — отличить страницу среди десятка открытых.

«МЦ» набрано обычной насыщенностью, не жирной: знак рядом тонкий, и полужирное
спорило бы с ним по цвету линии. Главным его делает кегль, а не утолщение.

«r» и «e» в знаке стоят на одной базовой линии и одного роста — как обычные
буквы. Круг выходит за строку сверху и снизу ровно на пол-единицы: это
оптический вынос, без которого круглая буква рядом с прямой кажется мельче её.
Разводить их по росту пробовали дважды, и оба раза выходило криво — строка
читалась не набором, а тремя предметами, поставленными рядом. Своё у знака —
толстые точки: они заметно толще линии букв, и это единственное место, где
пропорции нарочно не типографские. Из-за свеса «e» низ рисунка базовой
линии не равен, поэтому рисунок сдвинут вниз ровно на этот свес — тогда на
базовую линию «МЦ» встаёт строка «r», как и должно. Размеры заданы в em от
кегля шапки: на узком экране всё уезжает вместе, одним изменением кегля.

Перекладина «e» и его дуга — один контур: раздельными они давали на стыке
торчащий уголок.

**Гарнитура своя и лежит рядом — Golos Text.** Не по прихоти: сайт целиком
русский, а системные интерфейсные шрифты рисуют кириллицу как приложение к
латинице. Golos Text рисовалась от кириллицы, и на здешних словах — вроде
«Комбинаторная геометрия» — это видно сразу. Сравнивались три (ещё Inter и IBM
Plex Sans); Inter отпала не по качеству, а по узнаваемости: её ставят так часто,
что она читается шрифтом по умолчанию, а от этого ощущения мы как раз и уходили.

Файлов два, `assets/fonts/golos-{cyrillic,latin}.woff2`, 22 и 38 КБ. Разбиение
по `unicode-range`: кириллический берётся всегда, латинский только когда на
странице попадётся латиница. Оба переменные, 400–700 в одном файле, поэтому
любая насыщенность бесплатна. Стороннего запроса нет — файлы свои; кириллический
ещё и предзагружается, чтобы текст не мигал системным начертанием.

Стопки при этом всё равно две. Пока шрифт летит (или не долетел вовсе), крупное
и мелкое подхватывают разные системные начертания, а не одно на всё: `--font-ui`
в текст, `--font-display` в шапку, заголовки, значения плиток, счёт и ярлыки
разделов.

Взято с Google Fonts (SIL OFL). Обновить или сменить:

```
curl -sA "Mozilla/5.0 Chrome/120" \
  "https://fonts.googleapis.com/css2?family=Golos+Text:wght@400..700"
```

— в ответе ссылки на woff2 по диапазонам, нужны `cyrillic` и `latin`.

Заголовки и подписи разведены по кеглю сильно и нарочно: 21 против 11 в
разделах, 31 против 11 в плитках. На этом контрасте страница и держится.

Между 31 у плитки и 15 у текста долго не стояло ничего, хотя сайт — табло, и
его главная величина это счёт. Теперь столбец «Очки» набран 19-м: он и есть то,
ради чего таблицу открывают.

В строках рейтинга — полоска доли от собственного потолка, у первого места
золотой номер, у остальных стрелка изменения места после последней серии.

**На экране шире тысячи пунктов кондуит крупнее, а стоит посередине.** Он был
рассчитан под палец на телефоне и на мониторе выглядел миниатюрой в углу панели:
клетка 38, знак плюса 30, значок темы в шапке столбца 14, фамилия обрезана на
десятом знаке, справа пустота в пол-панели. Теперь клетка 52, строка 48, плюс
40, значок 20, а столбцу фамилий хватает ширины на любую.

Растягивать таблицу клеток во всю ширину пробовали — вышло хуже: восемь столбцов
разъезжались до семидесяти пяти пунктов при знаке в сорок, и сетка переставала
читаться сеткой. Десять столбцов просто не заполняют девятьсот пунктов при
вменяемом размере клетки. Поэтому обе половины стоят посередине панели: пустота
осталась, но поровну с двух сторон — такая читается полем, а не обрывом.

Обе половины кондуита поднимаются в высоте вместе: разъедься они хоть на
пиксель, строки перестанут совпадать. Ширина задана и итоговым столбцам
(«всего», «был») — без неё они плавали от того, какое число в них попало, и
правый край кондуита гулял от серии к серии.

Прокрутка приручена в трёх местах. При смене вкладки страница сначала
отматывается наверх — на глазах, со старым содержимым, — и только потом оно
сменяется: прыжок туда читался бы как сбой, а листать пустоту непонятно. При
открытии карточки ученика, наоборот, список наверх не мотается: он пролетел бы
весь: страница гаснет, и переход к началу делается на погасшем экране. При
перерисовке на месте (сменили отбор) прокрутка держится: опустевший на мгновение
экран короче, и браузер прижимал её к началу.

Движение — дополнение, а не событие, и работает только там, где показывает
смысл. У смены экрана оно показывает направление: открыли карточку ученика — она
приходит снизу, будто шагнули вглубь; вернулись в список — он опускается сверху,
тем же путём назад; сменили вкладку — движение нейтральное, соседний экран не
глубже и не выше. Сдвиг при этом крошечный, восемь-двенадцать пикселей: это
подсказка о направлении, а не переезд. Уход короткий и с разгоном, приход длиннее
и с торможением — тогда смена читается как одно движение вперёд, а не как две
одинаковые половины.

Так же и в остальном: строки рейтинга переезжают на новые места при смене
отбора, касание номера задачи в кондуите гасит остальные столбцы. Перекличка
строк по очереди убрана — на списке в три десятка человек она читалась не как
оживление, а как ожидание. Всё снимается системной настройкой «уменьшить
движение».

Плоскими остались клетки кондуита и кружки тем: там важна не красота, а то,
чтобы разница между «решено» и «нет» читалась с одного взгляда.

Прежнее оформление помечено тегами: `design-1` — плоское, `design-2` — то же,
но с крупной шапкой сезона. Вернуть любое:

```
git checkout design-1 -- assets index.html edit.html
```

## Ссылка и Chrome

Ссылка, отправленная в мессенджере, открывается во встроенном браузере
приложения: там нет ни установки на домашний экран, ни нормального кэша.
Заставить обычный `https://` открыться именно в Chrome нельзя, поэтому для
рассылки есть отдельный адрес:

```
https://<ник>.github.io/<репозиторий>/open.html
```

Он смотрит, откуда его открыли, и уходит в Chrome: на Android — адресом
`intent://` с указанием пакета браузера, на iPhone — через `googlechromes://`.
Если Chrome не установлен или не отозвался, остаётся обычный сайт. Из самого
Chrome прыжка не происходит — открывается сразу.

Себе и всем, кто пользуется сайтом постоянно, лучше **добавить его на домашний
экран**: есть манифест, и тогда он открывается отдельным окном, без адресной
строки и без чужого браузера внутри приложения.

## Как обновляется сайт

Любая правка в ветке `main` выкладывается GitHub Pages сама, обычно меньше чем
за минуту. Отдельной кнопки «опубликовать» нет.

После правки стилей или скриптов нужно проставить версию — иначе браузер
телефона неделю показывает старый кэш:

```
python tools/build.py
```

## Развёртывание

1. **Settings → Pages**: источник — ветка `main`, папка `/ (root)`. Через минуту
   сайт открывается по адресу `https://<ник>.github.io/<репозиторий>/`.
2. В `data/config.json` — `repo.owner` и `repo.name`: редактор пишет правки
   именно туда. Пока они не совпадают с настоящим репозиторием, сохранение
   честно скажет, что не нашло его.
3. Fine-grained токен: **Settings → Developer settings → Personal access tokens
   → Fine-grained tokens**, доступ только к этому репозиторию, право **Contents:
   Read and write**. Вставить в редакторе во вкладке «Сохранение» и нажать
   «Проверить доступ».
4. Открыть `edit.html` на телефоне и добавить на домашний экран — дальше он
   открывается как приложение.

Репозиторий можно держать публичным: `robots.txt` и `noindex` держат страницу
вне поиска, а писать в неё всё равно может только владелец токена.
