# Кондуит

Внутренняя версия кондуита математического кружка 11 класса, 2026/27.
Учёт плюсов на занятиях: кондуит по сериям, общий рейтинг и пересчёт рейтинга
по любому подмножеству серий и тем.

Сервера и базы данных нет. GitHub Pages раздаёт репозиторий как есть, страница
читает файлы из `data/` и считает всё в браузере читателя. Читать может кто
угодно по ссылке, писать — только владелец репозитория.

## Счёт

Вес задачи = **max(n − число решивших, 1)**, где n — сколько человек занималось
по этой серии, то есть длина её списка. Задачу, которую сдали трое из двадцати,
она оценит в 17; задачу, которую сдали все, — в 1: решена же.

Список свой у каждой серии, поэтому и n у них разное: задача, которую давали
десятерым, и задача на весь кружок стоят по-разному. Гробы к занятию не
привязаны и считаются от всего списка группы.

У задачи бывает **своя цена** — тогда формула к ней не применяется. Формула
знает одно: сколько человек сдали. А задача бывает дорога и не поэтому. Своя
цена ставится у каждой задачи отдельно, и её всегда можно вернуть к формуле.
Ноль руками поставить можно: это не то же самое, что «нет своей цены».

У гроборешения бывает **надбавка** — сколько добавить за конкретное «кто взял
этот гроб». Она прибавляется к цене гроба и достаётся только тому, кому
поставлена.

В рейтинге сначала очки, при равенстве — по алфавиту; одинаковых мест не
бывает. В кондуите ученики стоят по алфавиту: там ищут человека, а не место.

## Что где лежит

```
index.html          сайт: рейтинг, кондуит по сериям, гробарий, зачёт, карточка
edit.html           редактор: ввод с телефона
open.html           ссылка для рассылки: уводит из встроенного браузера в Chrome
manifest.webmanifest  установка на домашний экран
assets/             стили, скрипты, значки
data/
  config.json       название, репозиторий, подпись
  students.json     ученики
  types.json        темы: разделы и подразделы
  graves.json       гробарий: задачи вне серий и кто их взял
  series/NN.json    одна серия
  series/manifest.json  список файлов серий
  pdf/*.pdf         листки серий и гробария
  zachet.json       список файлов зачёта
  zachet/*.pdf      файлы зачёта
tools/build.py      версия статики (после правки стилей и скриптов)
```

Формат серии:

```json
{
  "n": 7,
  "series": 5,
  "given": "2026-09-12",
  "date": "2026-09-15",
  "held": true,
  "roster": ["ivanov-artem"],
  "present": ["ivanov-artem"],
  "problems": [
    { "id": "0", "type": "algebra", "sub": "inequalities", "exercise": true },
    { "id": "2а", "type": "comb", "sub": "graphs", "exercise": false, "weight": 12 }
  ],
  "pdf": { "file": "seriya-07.pdf", "size": 124035, "at": "2026-09-12" },
  "solved": { "ivanov-artem": ["2а"] }
}
```

`series` — номер серии, он и виден на сайте. `n` — служебный слот: он же имя
файла и ключ внутри редактора; менять его нельзя, иначе перенумерованная серия
потеряет свой файл. `given` — когда серию выдали, `date` — когда было занятие.
`weight` есть только у задач со своей ценой.

**Список серии** (`roster`) — кто по ней занимался. Заводится он с общего списка
на тот день, когда серию завели, и дальше за ним не следует: уехавшие на сборы,
финал или турнир занятие не пропустили — его у них просто не было. Из этого
списка считается n, по нему же построен кондуит. Общий список задаёт имена:
переименование ученика видно сразу всюду, а состав прошлых серий не трогает.

**Посещаемость** (`present`) — последний столбец кондуита, рядом с плюсами. По
умолчанию отмечены все: снимать проще тех, кого не было. В карточке ученика
видно «Занятия n / m», пропущенная серия помечена «не был», а в рейтинге есть
отбор «где все были» — по сериям, на которых был весь их список.

**Занятие ещё не прошло** (`held: false`) — серию выдали, темы расставлены,
листок приложен, а кондуит по ней на сайте не показывается и нигде не считается.
Вкладка «Сохранение» напомнит, если в такой серии уже стоят плюсы.

Выбывший ученик помечается в `students.json` полем `out`, а не стирается: его
имя стоит в кондуитах тех занятий, где он был. В общем списке и в рейтинге его
больше нет; вернуть — завести с тем же именем.

Упражнение узнаётся по номеру: числовая часть равна нулю (`0`, `0а`) — значит
упражнение. Поле `exercise` лишь повторяет это в файле.

Задача, чей подраздел удалили из тем, остаётся **без темы**: в рейтинг она не
идёт, пока ей не выберут тему заново, но в кондуите видна — с серой полоской.
Вкладка «Сохранение» показывает такие задачи списком.

## Редактор

`edit.html` открывается в браузере телефона. Один раз нужно вставить
fine-grained токен GitHub с доступом только к этому репозиторию и правом
**Contents: Read and write** — вкладка «Сохранение». Токен лежит в localStorage
телефона и уходит только на `api.github.com`; если телефон потерялся, токен
отзывается в настройках GitHub.

Правки живут в памяти страницы и уезжают **только по кнопке «Сохранить»** во
вкладке «Сохранение»: она одна отправляет всё накопленное — учеников, темы,
серии, гробарий, зачёт, настройки. Уход со страницы теряет несохранённое, ничего
не переспрашивая; переключение между вкладками и сериями — нет. Рядом кнопка
отката. Между сохранениями две минуты перерыва.

- **Серии** — лента по номерам. «+ серия» заводит новую сразу в ленте, в
  репозиторий она уедет по кнопке сохранения. Первое «+ задача» даёт упражнение
  (номер 0), дальше номера идут подряд. «+ пункт» превращает задачу `5` в `5а` и
  добавляет `5б`; пунктов не больше шести. Касание клетки ставит и снимает плюс,
  последний столбец — посещаемость. Внизу экрана листок серии и её список: их
  правят редко, потому они и внизу.
- **Гробы** — задачи вне серий, копятся весь год. Там же листок гробария и
  список гроборешений: кто, какой гроб, какая надбавка.
- **Зачёт** — pdf, которые надо раздать.
- **Темы** — разделы и подразделы. Удаление раздела освобождает его цвет;
  последний раздел удалить нельзя.
- **Ученики** — список группы. Имя правится прямо в строке: id при этом не
  меняется, поэтому плюсы не теряются. Плюсы удалённого остаются в файлах серий:
  считаться перестают, но вернутся, если завести человека снова.
- Любой pdf выбирается прямо с телефона, до 8 МБ, и уезжает той же кнопкой
  сохранения. Файлы уходят раньше записей, которые на них ссылаются.
- Приложенный листок везде так и называется — «Листок»: чей он, видно по месту.
  Осмысленное имя получает скачанный файл: «Серия 5.pdf», «Гробарий 1 сентября
  2026.pdf». Имя файла в репозитории закреплено за записью, поэтому новый листок
  просто ложится поверх старого.
- Удаление где угодно спрашивает дважды: крестик раздваивается на «удалить» и
  «передумал».

## Чтобы редактором нельзя было испортить сайт

- Список серий не считается по памяти страницы: при каждом сохранении он берётся
  из самой папки `data/series`, плюс записанное сейчас, минус удалённое. Любое
  расхождение уходит при ближайшем сохранении само. Пустой список не пишется.
- Файл, о котором редактор не знает, не переписывается: это всегда чужие данные.
- Непрочитанное не правится: если список серий, гробарий или зачёт не
  загрузились, вкладка показывает сообщение, а не пустой список.
- Настройки не пишутся памятью страницы: файл перечитывается перед записью, и
  меняется в нём одно поле — то, которое правили.
- Сайт переживает порчу данных: пропавший файл серии пропускается, пропавший
  список серий — тоже; страница откроется без серий, но откроется.

## Оформление

Страница рассчитана на **Chrome** — и на телефоне, и на компьютере. Прежняя
осторожность с градиентами была нужна из-за Samsung Internet: тот в
принудительной тёмной теме гасил именно их. Это требование снято, и оформление
построено на прозрачности.

Подложка — неподвижный слой с тремя цветными пятнами и тетрадной клеткой
поверх. Неподвижный он не для красоты: любое его движение заставляло бы браузер
пересчитывать размытие всех панелей на каждом кадре.

Всё остальное — матовое стекло: полупрозрачная заливка, размытие того, что под
ней, светлая грань поверху вместо рамки и мягкая тень. Стекло только у крупных
панелей — карточек, таблиц, кондуита, полосы вкладок и шапки сезона. У кнопок и
ярлыков своего размытия нет: их на экране десятки, а каждое стоит кадра — им
хватает прозрачной заливки поверх уже размытой панели.

Размытие задано одной переменной `--pane-blur`. Если где-то окажется дорогим —
поставить в ней `none`, и стекло станет просто прозрачным, ничего не разъедется.
Там, где `backdrop-filter` недоступен вовсе, панели становятся плотными.

Полоса вкладок — плавающая пилюля: она висит над содержимым, и под ней всё
проезжает. Выбранная вкладка помечена указателем, и указатель этот один на всю
полосу — он переезжает с вкладки на вкладку.

Переход браузера (View Transitions) здесь пробовался и убран совсем: он
подменяет снимками всё окно — из-за этого дёргалась шапка, замирал указатель и
путалась прокрутка при открытии ученика из середины списка. Любая смена экрана
теперь одна и та же: содержимое уходит за 90 мс и приходит новое, а шапка,
полоса вкладок и указатель всё это время остаются живыми элементами страницы.

Украшающего цвета нет вовсе — только свет. Пятна на подложке белые, панели
подсвечиваются белым, у каждой светлая грань сверху, тёмная снизу и косой блик
поверх. Цветными остались лишь те места, где цвет что-то значит: кружок раздела
и полоска над столбцом в кондуите, золото первого места, значок редактора.

Подложка нарочно не белая и с заметной клеткой: сквозь прозрачную панель должно
быть что-то видно, иначе стекло сливается с фоном и перестаёт быть стеклом.

Механика подкраски при этом на месте: у блоков пять слотов оттенка (`--tint-a`
… `--tint-e`), сейчас все белые. Чтобы подкрасить один блок, достаточно
заменить его слот — цвет появится точечно и ровно там, где нужен.

Панель одна на всех: карточка, плитка, таблица рейтинга и кондуит собраны из
одного набора правил и выглядят одним материалом. Всё, что делало их разными —
своя подкраска у таблицы, заливка у шапки столбцов, отдельный слой под
подсветку, — убрано.

Цена оформления на телефоне держится в трёх правилах.

**Размытие подложки — только у полосы вкладок.** Под ней проезжает содержимое,
и там оно работает. У панелей его нет: под ними ровный свет и клетка, размывать
нечего, а платить пришлось бы на каждом кадре и заново при каждой вставке панели
в страницу. Прозрачность, грани и блик держат стекло и без размытия.

**У нового экрана нет появления.** Он показывается разом и уже собранным: пока
он проявлялся, было видно, как страница складывается — особенно на рейтинге, где
строк три десятка. Плавность даёт уход старого экрана, приход должен быть
мгновенным.

**Фон — закреплённая заливка самого `html`, а не слой поверх страницы.** Он
неподвижен: не прокручивается с содержимым и не смещается, когда на телефоне
появляется и исчезает адресная строка. Закреплённым слоем (`position: fixed`)
этого не добиться — такой слой браузер как раз и двигает вслед за окном. Рисунок
простой, две линии и три пятна, поэтому закреплённая заливка обходится дёшево.

Ярлыки отбора, наоборот, спокойные: скруглённые прямоугольники, цвет раздела в
них — только кружок и намёк в рамке. Заливать их цветом пробовали: десяток
плашек в ряд рябит и спорит с самим кондуитом. Пилюли остались за полосой
вкладок и мелкими действиями.

Заголовки и подписи разведены по кеглю сильно и нарочно: 21 против 11 в
разделах, 31 против 11 в плитках. На этом контрасте страница и держится.

В строках рейтинга — полоска доли от собственного потолка, у первого места
золотой номер, у остальных стрелка изменения места после последней серии.

Прокрутка приручена в трёх местах. При смене вкладки страница сначала
отматывается наверх — на глазах, со старым содержимым, — и только потом оно
сменяется: прыжок туда читался бы как сбой, а листать пустоту непонятно. При
открытии карточки ученика, наоборот, список наверх не мотается: он пролетел бы
весь: страница гаснет, и переход к началу делается на погасшем экране. При
перерисовке на месте (сменили отбор) прокрутка держится: опустевший на мгновение
экран короче, и браузер прижимал её к началу.

Движение — дополнение, а не событие: карточки поднимаются на четыре пикселя,
и всё. Перекличка строк по очереди убрана: на списке в три десятка человек она
читалась не как оживление, а как ожидание. Работает только там, где показывает
смысл: строки рейтинга переезжают на новые места при смене отбора, а касание
номера задачи в кондуите гасит остальные столбцы. Всё снимается системной
настройкой «уменьшить движение».

Плоскими остались клетки кондуита и кружки тем: там важна не красота, а то,
чтобы разница между «решено» и «нет» читалась с одного взгляда.

Прежнее оформление помечено тегами: `design-1` — плоское, `design-2` — то же,
но с крупной шапкой сезона. Вернуть любое:

```
git checkout design-1 -- assets index.html edit.html
```

## Ссылка и Chrome

Ссылка, отправленная в мессенджере, открывается во встроенном браузере
приложения: там нет ни установки на домашний экран, ни нормального кэша.
Заставить обычный `https://` открыться именно в Chrome нельзя, поэтому для
рассылки есть отдельный адрес:

```
https://<ник>.github.io/<репозиторий>/open.html
```

Он смотрит, откуда его открыли, и уходит в Chrome: на Android — адресом
`intent://` с указанием пакета браузера, на iPhone — через `googlechromes://`.
Если Chrome не установлен или не отозвался, остаётся обычный сайт. Из самого
Chrome прыжка не происходит — открывается сразу.

Себе и всем, кто пользуется сайтом постоянно, лучше **добавить его на домашний
экран**: есть манифест, и тогда он открывается отдельным окном, без адресной
строки и без чужого браузера внутри приложения.

## Как обновляется сайт

Любая правка в ветке `main` выкладывается GitHub Pages сама, обычно меньше чем
за минуту. Отдельной кнопки «опубликовать» нет.

После правки стилей или скриптов нужно проставить версию — иначе браузер
телефона неделю показывает старый кэш:

```
python tools/build.py
```

## Развёртывание

1. **Settings → Pages**: источник — ветка `main`, папка `/ (root)`. Через минуту
   сайт открывается по адресу `https://<ник>.github.io/<репозиторий>/`.
2. В `data/config.json` — `repo.owner` и `repo.name`: редактор пишет правки
   именно туда. Пока они не совпадают с настоящим репозиторием, сохранение
   честно скажет, что не нашло его.
3. Fine-grained токен: **Settings → Developer settings → Personal access tokens
   → Fine-grained tokens**, доступ только к этому репозиторию, право **Contents:
   Read and write**. Вставить в редакторе во вкладке «Сохранение» и нажать
   «Проверить доступ».
4. Открыть `edit.html` на телефоне и добавить на домашний экран — дальше он
   открывается как приложение.

Репозиторий можно держать публичным: `robots.txt` и `noindex` держат страницу
вне поиска, а писать в неё всё равно может только владелец токена.
